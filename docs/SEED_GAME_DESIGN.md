## 1. 한 줄 설명
구역 깊숙이 들어가 **씨앗을 훔쳐** 안전 구역으로 달려오고, 내 **정원**에 심어 새싹 → 식물 → **성체**까지 키워 코인을 벌고 도감을 채우는 게임.

## 5. 정원 키우기 (본부장 제안, 사장님 "추가")

- 성체 식물은 가끔 **열매**를 떨어뜨림(등급 높을수록 좋은 열매). 열매는 **코인으로 팔기만** (9판 2026-11-10: 다른 식물에 먹여서 돌연변이를 붙이던 "먹이기"는 사장님이 **완전히 없앰** — 9장 52번).
- 밤에는 성체까지 가는 시간도 30배 빨라짐(지금 밤 규칙 그대로).
- 정원에서 할 일이 생겨서 씨앗 훔치러 안 나갈 때도 심심하지 않음.
- 물 주기: 없음 (사장님 2026-10-28 삭제).

## 6. 씨앗의 모양·아우라
- 씨앗: 작은 타원(지금 알 모양 재사용) + 등급 색 + 아우라 파티클(3장 표). 특별 씨앗(비밀 이상)은 빛기둥·이름표(500 스터드 안).
- 자라는 모습: 새싹(0~25%) → 줄기+잎(25~60%) → 봉오리(60~99%) → 성체(100%, 식물마다 다른 모양·열매). 성체 위에 코인/초 표시.
- 식물 종류: 182종(6판 134종 + 7판 새 구역 3개 × 8종 + 8판 새 구역 3개 × 8종) — 이름·모양은 **우리가 새로 지음** (사장님 아이디어 환영: 예 "불꽃 해바라기", "얼음 선인장", "별 버섯").
- 8판 크기: 등급이 높을수록 성체가 크고(일반 ×1 → 해커 글리치 ×4.5), 새싹 0.3 → 줄기 0.55 → 봉오리 0.8 → 성체 1 로 **점점** 커짐 (9장 41번).

## 7. 사장님 결정 (2026-10-27)
1. 성체 식물은 **열매를 따서 팔아야** 코인이 됨 (자동 코인 없음). → 성체는 일정 시간마다 열매를 맺고, 플레이어가 정원에서 열매를 따서(프롬프트) 판매 가판대에 팔기. 등급·돌연변이가 높을수록 열매 값 ↑, 열매 맺는 간격 ↓. 안 따면 열매는 식물당 최대 N개(제안 5)까지만 쌓임.
2. 코인은 **게임 안 돈(무료)**. 로벅스 건너뛰기는 나중에(어른 확인).
3. 밤 30배 성장 **그대로**.
4. **제단(12번 천사&악마) 없앰**. **사쿠라 나무는 씨앗 버전으로 남김**: 남는 식물을 바치면 크리스탈, 크리스탈로 특별 씨앗 뽑기(블룸 → "벚꽃 씨앗", 스피릿 블룸 → "정령 벚꽃 씨앗"). **퓨전 머신도 없앰**(사장님 결정). 특별 장소는 사쿠라 나무(씨앗 버전) 하나만 남음.
5. 경비는 **식물 괴물**로 바꿈 (예: 1 숲 식충 식물, 2 호수 연꽃 개구리풀, 3 사막 가시 선인장, … 14 사탕 왕국 사탕수수 거인, 15 유령 성 호박 머리 덩굴). 이름·모양은 우리가 새로 지음.
6. (추가 지시) **러닝머신 최대 1초 1M**: 러닝머신을 끝까지(20레벨) 올리면 1초에 속도 **1,000,000** 이 오름 (9장 18번, 14장).

55. **러닝머신 레벨 상품**: `tskip_N` 은 러닝머신 레벨이 **정확히 N-1** 일 때 N 으로 올림 (코인 안 듦). 화면은 지금 레벨의 다음 상품만 보여 줌 (`Products.nextTreadmillSkip(level)`). 그래도 레벨이 안 맞게 오면 (창이 늦게 바뀜·두 번 누름·위조 클라) **산 로벅스만큼만** 줌 (58번 — 처음 9판의 "다음 1칸 · 최대면 속도 600M"은 주임 F-3 로 바꿈). 기존 코인 업그레이드 `PurchaseUpgrade("Treadmill")` 는 그대로.
56. **서버 권위 지급** (`src/server/Services/ProductService.luau`): `MarketplaceService.ProcessReceipt` 하나 — 플레이어가 없거나 데이터를 불러오는 중(15초까지 기다림)이면 `NotProcessedYet` (로블록스가 나중에 다시 부름), 영수증 `PurchaseId` 가 `data.receipts`(최근 `Config.RECEIPT_HISTORY_MAX` 500개 고리 — 58번)에 있으면 이미 준 것이라 그냥 `PurchaseGranted`, 모르는 상품 id 면 `NotProcessedYet`(경고 — 처리 안 된 구매는 로블록스가 다시 알려 주고, 끝내 처리 안 되면 환불될 수 있음), 아니면 영수증을 먼저 적고 지급(`ProductService.grant(player, key, source)` — 순수 지급 로직, 개발 명령 `/buy <key>` 도 같은 함수) → 저장(`DataService.save`) 성공이면 `PurchaseGranted`, 실패면 `NotProcessedYet` (메모리에 영수증이 남아 이번 접속에서 다시 와도 두 번 안 줌). 스튜디오 메모리 모드는 저장 없이 `PurchaseGranted`. 지급되면 서버 → 클라 **`ProductGranted`** `{ key, kind }` + `DataUpdate("upgrades")`(`treadmillBoost`·`moneyPass`·`treadmillLevel`) + Attr `TreadmillBoost`·`MoneyPass`. 서버로 "사 줘" Remote 는 **일부러 없음** (구매창은 클라 `PromptProductPurchase`). **저장 스키마 8**: `treadmillBoost = 1` · `moneyPass = false` · `receipts = {}` 추가 (7 → 8 은 칸만 추가, 15장).
57. **버그 수정: 씨앗을 든 채 밤이 되면 그 씨앗이 가방에 들어옴** (사장님 D): 밤이 되면 서버가 허브 밖 사람을 베이스로 순간이동시키는데, 베이스가 허브(안전 구역) 안이라 다음 0.2초 틱에 "씨앗을 들고 허브에 들어옴 = 배달" 로 쳐서 가방에 들어갔음 (8판까지는 일부러 그렇게 했던 것). 이제 **서버 순간이동으로 허브에 들어오면 배달이 아님** — 순간이동하기 전에 든 씨앗을 원래 둥지(없으면 같은 구역 빈 둥지)로 돌려보내고 "밤이 되어 씨앗이 둥지로 돌아갔어요." 안내 (`BaseService.returnCarriedBeforeTeleport` · `EggService.returnCarriedToNest`). 같은 구멍: 늦게 받은 베이스로 집 순간이동, 개발 명령 `/zone`(어느 구역이든 — 씨앗을 들고 순간이동 못 함)도 같이 막음. 안티치트 되돌림(1초 전 정상 위치로)은 씨앗을 든 채 허브 밖에 있던 자리로만 돌아가서 구멍이 아님 (허브 안이었다면 그때 이미 배달됐음). 스스로 걸어서 허브에 들어온 정상 배달은 그대로. 씨앗을 놓쳤으니 튜토리얼 2단계였으면 1단계로 (다시 훔치기).

### 9-10. 2026-11-10 사장님 고침 (위 33·40·41·54번보다 이것이 먼저)

59. **스피드 배수는 순서대로 열림** ("2배를 사야 4배가 열리는 식"): 바로 다음 배수만 살 수 있음 (`Products.nextTreadmillBoost` · `treadmillBoostState` · `treadmillBoostOutcome`, 54번 참고). 2048배까지 합계 4,094 R$.
60. **경비는 진짜 닿아야만 잡음** ("무조건 잡혀야 날아가지 · 안 잡혔는데 왜 몇 초 뒤 확정 날아감" · "부딪혀도 안 날아가는 버그"): 잡힘 = 경비가 쫓는 중이고 수평 거리 ≤ 잡힘 거리(`CatchDistance` = 6 + 키 × 0.25, 최대 16)일 때만. 40번의 시간(2.5초 / 1초)으로는 **아무 일도 안 일어남** ("초 지나면 잡힌다고!" — 시간이 됐다고 날아가지도, 경비가 빨라져 달려들지도 않음. 돌진 삭제, 경비는 언제나 구역 고정 추격 속도). 화면의 초 카운트다운 글도 없앰. 41번과 달리 **도망칠 수 있는 빠른 사람도 경비에 부딪히면 잡힘**. 도망칠 수 없는 채로 다음 구역 경계를 넘으면 즉시 잡히는 것은 그대로.
61. **자기 구역 안에서 떨어뜨리면 바로 둥지로** ("자기 구역 안에서 떨어뜨리면 바로 둥지로 돌아간다"): 그 씨앗의 구역 안에서 놓치면 원인이 무엇이든 (버리기 · 방망이 · 곰덫 · 경비) **바로 둥지로** (`EggRules.dropOutcome` → `"ReturnToNest"`). 구역 **밖**에서 놓치면 그 자리에 떨어졌다가 **5초 뒤** 둥지로 (그 사이 누가 주우면 취소, `EggRules.groundFate` 는 언제나 `"Return"`). 33번의 "구역 안 = 그 자리에 그대로"는 본부장이 잘못 읽은 것 — 없앰.
62. **영구적인 것은 게임패스, 소모품은 개발자 상품** (사장님 2026-11-10 — 53·56번보다 이것이 먼저): 36개 중 **게임패스 12개** = `boost_2` … `boost_2048`(11) + `money_pass` (`Product.isPass = true`, 한 번만 삼), **개발자 상품 24개** = `tskip_1` … `tskip_20` · `coins_1m` · `coins_1b` · `speed_10m` · `speed_100m` (지금 로직 그대로 — `ProcessReceipt`·영수증 기록·`treadmillSkipOutcome`). 가격은 그대로. id 는 그대로 `Products.IDS` 한 표 (`productId` 칸 — 패스면 gamePassId, 주석 `[게임패스]`·`[개발자 상품]`으로 구분, 지금은 전부 0). `Products.byProductId` 는 **개발자 상품만** (패스 id 로 영수증이 와도 "모르는 상품" → 지급 없음), `Products.byPassId` 는 패스만, `Products.passes`(12). 구매창은 클라 `Purchase.prompt` 가 패스면 `PromptGamePassPurchase`, 아니면 `PromptProductPurchase` (창 닫기는 두 Finished 이벤트 다). 패스는 영수증이 **안 오므로** 서버가 소유 확인(`UserOwnsGamePassAsync`, pcall · 실패하면 2번 더 · 사이 1초)으로만 반영: ① 접속 준비 때 `ProductService.syncPasses(player)` (id 붙은 패스 전부 동시에) → `data.moneyPass = 원래 값 or 가짐`, `data.treadmillBoost = max(원래 값, Products.boostFromOwnedPasses(가진 배수들))` — **절대 낮추지 않음**, 확인이 전부 실패하면 그대로. ② 서버 `PromptGamePassPurchaseFinished` 가 `wasPurchased` 로 오면 소유를 다시 확인해서 **true 일 때만** 반영 + `ProductGranted` (같은 패스는 접속당 1번) · 안내 · `stats.productsBought` · 저장 시도, 확인이 안 되면 지급 없이 "구매를 확인하는 중이에요. 잠시 뒤 다시 접속하면 적용돼요". 게임패스는 웹(게임 페이지 상점)에서 **순서를 건너뛰어** 살 수 있으므로 `boostFromOwnedPasses` = 예산(가진 패스 가격 합)으로 2배부터 차례로 올릴 수 있는 데까지 (59번 순서 규칙 + 낸 값만큼은 받게): {2,4,8} → ×8 · {2048} → ×1024 · {4} → ×2 · {2,8} → ×4. 개발 명령 `/buy` 는 스튜디오 시험용으로 패스 key 도 바로 줌 (진짜 서버에서는 패스는 소유 확인으로만). 아빠 안내 `docs/ROBUX_SETUP.md` (패스 12개 = Monetization → Passes, 상품 24개 = Developer Products, 패스 id 와 상품 id 를 섞지 말 것, 부스트 패스는 2배부터 차례로 다 붙일 것).

- 6 → 7 (7판 성장 3배): 정원에 심은 씨앗(incubators)·가방 씨앗(eggs)의 progress 를 "자란 비율" 이 같게 새 required(표 시간 ÷ 3)에 맞춤 (`DataSchema.rescaleProgress`). 저장 데이터에는 등급 id 가 없어서 등급 16개로 바뀌어도 보정할 칸은 없음 (옛 슈퍼 울트라디바인 식물 2종은 식물 id 그대로).
- 8판: 칸 모양이 안 바뀌어 스키마 7 그대로. 정원에 저장된 자리는 7판 간격으로만 다시 확인 (`EggPlacement.checkSaved` — 8판 큰 식물 간격 때문에 불러오다 식물이 팔리지 않게).
- 9판 (스키마 8): + `treadmillBoost`(러닝머신 부스트 배수, 기본 1 — 저장값 이하에서 가장 큰 파는 배수로 보정) · `moneyPass`(코인 2배, 기본 false — `true` 만 인정) · `receipts`(지급한 영수증 `PurchaseId`, 글자 1~64자, 중복 없이 최근 100개). 7 → 8 은 칸만 추가 (옛 데이터는 기본값). 열매 먹이기는 없앴지만 저장된 식물의 원소 돌연변이는 그대로 (`DataSchema.cleanMutations` 는 알려진 돌연변이만 남기고, 원소 3개는 표에 남아 있음).
